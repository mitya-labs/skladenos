# packages — deb-пакеты skladenOS

Всё, что раньше делали скрипты `scripts/*-setup/-install` на живом телефоне, переезжает в пакеты: образ собирается из них воспроизводимо.

| Пакет | Что | Статус |
|---|---|---|
| `skladenos-artwork` | логотип skladenOS (SVG: знак, горизонтальный/вертикальный, тёмный/светлый фон; иконки hicolor), логотип Mitya Labs (пёс) и фирменные обои «Skladen v2.1» с ним — **все права защищены**, `Section: non-free` (`assets/NOTICE.md`) | собран |
| `skladenos-wallpapers` | свободные обои «Skladen v2.1» без логотипа — **CC BY-SA 4.0** | собран |
| `skladenos-fonts` | DejaVu Sans Mono Nerd Font (Regular, Bold) — глифы значков SXMO; `fonts-nerd-symbols` из Debian не подходит (нет Material Design U+F0xxx, проверено на телефоне) | собран |
| `skladenos-config` | слой A — системные настройки: профиль устройства SXMO, ADSP/SLPI/звук, USB-гаджет, Wi-Fi powersave, вырез, планы питания, SXMO по умолчанию, шимы `superctl`/`doas`, `phone-nosleep`, `phone-usb`, `sxmo-safe-area` | собран, ставится в чистом Debian (smoke-тест) |
| `skladenos-config` | слой B — `skladenos-apply`: пользовательские настройки SXMO в `~/.config/sxmo` (sway с баром под вырез, хуки статус-бара/поворота/suspend, меню Scripts, клавиатуры, виджет часов), собираются из штатных шаблонов sxmo-utils; юнит `skladenos-apply.service` + postinst | собран и проверен тестом `packages/test-apply.sh` на настоящем sxmo-utils; на телефоне проверена генерация и сравнение с живым конфигом (STATE п.140), запуск на экране — нет.  Значки Nerd Font: хук `sxmo_hook_icons.sh` из шаблона + шрифт из `skladenos-fonts` |
| `skladenos-firstboot` | мастер первой загрузки: TUI (Textual) в `foot`, пока нет `/var/lib/skladenos/firstboot-done`: Bluetooth-клавиатура, Wi‑Fi, смена имени пользователя и пароля; запуск из sway (`/etc/sway/config.d/60-skladenos-firstboot.conf`), root-helper по `sudo` (`%sudo`), переименование отложено на следующую загрузку (`skladenos-firstboot-rename.service`). Демо без железа: `skladenos-firstboot --demo`; тесты: `python3 -m unittest discover -s packages/skladenos-firstboot/tests` | собран; бэкенды и UI проверены на заглушках (Mac), на телефоне не запускался |
| `skladenos-emu-jornada720` | эмулятор HP Jornada 720 (QEMU из форка qemu-jornada720, 16 патчей, база QEMU `v11.1.2`) в `/usr/lib/skladenos/jornada720`, лаунчер `skladenos-jornada720`, пункт меню Scripts; ROM свой (`~/roms/jornada720.bin`); сборка `packages/emulators/build-jornada720.sh` (Docker) | собран, **запущен на телефоне, работает** (0.1.1) |
| `skladenos-emu-psion` | эмулятор Psion 5mx (WindEmu, Qt5, ветка pmos) в `/usr/lib/skladenos/windemu`, лаунчер `skladenos-psion`; ROM свой (`~/roms/5mx_eng.bin`); сборка `packages/emulators/build-windemu.sh` | собран, **запущен на телефоне, работает** |
| `skladenos-emu-pumpkinos` | PumpkinOS (Palm OS, ветка pmOS), лаунчер `skladenos-pumpkinos` (копия дерева в `~/.local/share/skladenos/pumpkinos`); `Section: non-free` — в `licenses/` лежит лицензия Palm OS SDK, запрещающая распространение SDK-частей: **в публичный репозиторий не класть без решения**; сборка `packages/emulators/build-pumpkinos.sh` | собран, **запущен на телефоне, работает** |

Сборка: `packages/build.sh skladenos-config` → `out/packages/*.deb` (нужен Docker; пакеты `skladenos-emu-*` сначала собирают бинарники `packages/emulators/build-*.sh`). Репозиторий apt из этих deb: `repo/build.sh` (STATE п.158). Тест слоя B: `packages/test-apply.sh` (нужны собранные `skladenos-config` и `skladenos-wallpapers`).
Ядро собирается отдельно: `build/kernel/build.sh` (см. `build/kernel/UPSTREAM`).
Что не переносится в пакет: `apt-mark hold` (версии фиксирует сборка образа), часовой пояс и пользователь (личное), прошивки Qualcomm (`droid-juicer` извлекает их на самом телефоне).

Пользователь по умолчанию в образе — `skladen` (параметр `IMG_USER` у `build/image/build.sh`; пароль 1234). Пакет не зашивает имя: `skladenos-apply` берёт `SKLADENOS_USER` (`/etc/default/skladenos`) или первого обычного пользователя (uid 1000), sudoers (`sxmo-*`) выданы группе `%sudo`. Пока нет флага `/var/lib/skladenos/firstboot-done` (его создаёт мастер первой загрузки после смены пароля), sshd пускает по паролю только из локальных сетей (`/etc/ssh/sshd_config.d/10-skladenos.conf`; по флагу `skladenos-sshd-policy.path` удаляет файл и перечитывает sshd); ключи работают всегда.
